- source_spec: `spec-6b-execution-skeleton.md`
  summary: **`ColumnTable` costs 57,829 bytes and the implementation does not use a single one of its verbs** — the base `Table` carries every method the two operations actually call, and the whole adapter suite is green on it.
  evidence: Measured 2026-08-04, both artefacts built from this tree with nothing else changed: `ColumnTable` **809,784 bytes**, base `Table` **751,955 bytes**, `adapters/arquero/engine.test.js` 29/29 passing on each. The decision to move to `ColumnTable` was taken with the project owner against a premise that was true and turned out not to be the constraint — "`filter` and `select` are `undefined` on the base class and Arquero exports no standalone verb functions, so the choice was `ColumnTable` or a hand-written filter". The third route was not weighed because nobody had looked inside the verbs: `filter` reduces to `_filter`, which builds a `BitSet` and calls `table.create({ filter })`, and `select` reduces to a column set and `table.create({ data, names })` — and `create`, `BitSet` and every reader the operations need (`mask`, `totalRows`, `column`, `numRows`, `array`, `indices`, `isFiltered`, `isOrdered`, `columnNames`) are on the base class and are public. So the memory argument that decided it is fully preserved on the base class: shared columns, ~0.0 MB for a retained Source → Filter → Columns chain, one `Uint32Array` per filter link. What `ColumnTable` buys is the verbs *as methods*. The first version of this entry waved that away with AD-30 — an expression surface is forbidden in the MVP, and `escape()` compiles to one row object per row per condition — but that argument was checked on 2026-08-04 and it only covers **one** of the four kinds still without an executor. `executorGaps()` names union, join, computed and aggregate; a prototype diff shows all four map onto methods that exist *only* on `ColumnTable` (`union`/`concat`, `join`/`join_left`, `derive`, `groupby`+`rollup` — 39 methods separate the two classes and the adapter calls none of them today). Of those, only Computed genuinely wants an expression and is therefore hand-built regardless of AD-30. Union and Join are structural, and `rollup` runs through Arquero's own `op` helpers rather than user free text. So three of the four are cases where the verbs would actually be callable.
  status: **closed 2026-08-04 — put to the project owner and decided: `ColumnTable` stays, and this is not a debt.** Two things decided it. First, the byte cost is measured against **no gate at all**: `scripts/assert-single-file.mjs:57` prints the artefact size as a note and never asserts on it, and the architecture states no artefact-size budget — what is budgeted is memory (550 MB), and that figure is identical on both classes because the sharing behaviour is `create` + `BitSet` either way. Second, the forward cost of reversing is concrete while the saving is not: three of the four remaining Step kinds land on `ColumnTable`-only verbs, so a reversal now is very likely undone at story 8. Also recorded, because it is the reason this entry existed at all: the "owner-approved decision" the original status deferred to traced back to a recommendation of mine, and the owner had followed it rather than formed it — so there was no external approval protecting the choice, and the deferral was resting on nothing. The decision above is the first one actually taken with the measurements in hand. **Correction carried out while closing:** this entry previously quoted the acorn entry below as "58,829 bytes"; that entry says **58,843**. Three figures are in play and all three are real measurements of the same class difference against three different trees — 58,843 (story 6a's tree), 58,729 (this spec's Design Notes) and 57,829 (this tree, post-6b). **If artefact size ever becomes a product concern** — the owner named shipping a file to somebody as the case — the answer is a separate light viewer, not shrinking this application; explicitly not now.
