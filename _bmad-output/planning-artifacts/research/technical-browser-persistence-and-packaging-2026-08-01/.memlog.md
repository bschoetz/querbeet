- (decision) Scope of this run so far: R9's first sub-question ONLY, run ahead of the rest because a negative answer would invalidate PRD FR-25 as written. Not a full R9 run - storage cost at scale, eviction behaviour, the Package container (fflate vs JSZip) and the Parquet-inside-the-package question are all still open.
- (source) Lead-measured: IndexedDB gate probe, Playwright persistent profiles, Chromium 151 and Firefox 153, real file:// URLs, two directories, one browser restart. Sources and raw JSON in imports/idb-probe/.
- (claim) ref=[G1] status=verified class=architecture pub=2026-08 — GATE PASSED: IndexedDB works from a file:// origin in Chromium 151 and Firefox 153. open() in 3.0/6.0 ms, a 100,000x20 Source written and read back intact, and the data survives closing and relaunching the browser process on a persistent profile. PRD FR-25 is buildable as written.
- (claim) ref=[G2] status=verified class=architecture pub=2026-08 — The file:// origin is ONE SHARED BUCKET: a page in a different directory read the record and the full 100,000-row Source written by another directory's page, in both engines. No per-file or per-directory partition. Two copies of querbeet.html share one session; any other local HTML file can read querbeet's stored data. Cannot be fixed from inside querbeet.
- (claim) ref=[G3] status=verified class=architecture pub=2026-08 — navigator.storage.persist() NEVER SETTLES in Firefox 153 from file:// (still pending at an 8000 ms bound); Chromium 151 resolves in 0.2 ms with false. Persistent storage is not grantable from file:// in either engine. Never await persist() on the startup path - an unguarded await deadlocks initialization in Firefox. persisted() is safe in both.
- (claim) ref=[G4] status=verified class=performance pub=2026-08 — 100,000x20 plain rows cost 8,913,424 B stored (Chromium) / 9,960,184 B (Firefox), against ~94 MB for the same data in the JS heap (R6 [M9]) - roughly a tenth. put 304.6 ms / 731.0 ms, get 194.9 ms / 825.0 ms. Quota before any write: 10,737,418,240 B Chromium, 1,238,988,800 B Firefox.
- (assumption) Half-million-row figures (~45-50 MB stored, ~1.5 s Chromium / ~3.7 s Firefox write) are LINEAR EXTRAPOLATIONS from a single 100,000-row measurement, not measured. Storage engines are not obliged to be linear.
