- (claim) ref=[b-11] status=verified class=failure pub=2021 — The canonical 'canvas is blank when printing' bug, Mozilla 1696619, is RESOLVED INVALID: the cause was the browser's 'Print backgrounds' setting being off, not canvas. No retrieved evidence exists that a modern canvas chart fails browser print-to-PDF.
- (claim) ref=[d-2] status=verified class=api pub=2026-08 — Chart.js's decimation plugin requires a MUTABLE dataset: it stores the original as dataset._data and redefines the data property. Against querbeet's Object.freeze'd data that is a write to a frozen object.
- (decision) Round 2 is the measurement pass rather than a second web round. Round 1's open questions are overwhelmingly measurable, not searchable: in-place mutation of frozen input (open for 4 of 5 candidates), uPlot setSize/auto-resize (unevidenced), the hidden-container bug (reported 2019 against ECharts 4.2.1, closed stale not fixed), ECharts tree-shaken size in a real Vite build, whether Observable Plot's default stylesheet lands inside the serialized SVG, canvas-vs-SVG under real print-to-PDF, and the volume ceiling with its failure mode.
- (claim) ref=[M-print] status=verified class=measurement pub=2026-08 — Printed via Chromium's own print pipeline: the three SVG artefacts produce 95-131 words of real text carrying 21-35 app-formatted axis labels and zero raster images; the three canvas artefacts produce 12 words (page headings only) and six images each. Canvas raster resolution tracks devicePixelRatio exactly: 620x300 at scale 1, 1240x600 at 2, 1860x900 at 3.
- (claim) ref=[M-frozen] status=verified class=measurement pub=2026-08 — No candidate (handbuilt, uPlot 1.6.32, Chart.js 4.5.1, Observable Plot 0.6.17, ECharts 6.1.0 in both renderers) throws on Object.freeze'd input or mutates it. Gate G5 passed by all six. Chart.js's decimation plugin was off by default and not enabled.
- (claim) ref=[M-volume] status=verified class=measurement pub=2026-08 — 500,000 raw line points with no decimation on any candidate: uPlot 54.7 ms (Chromium) / 60 ms (Firefox), handbuilt 117.7/140, Chart.js 185.0/114, ECharts canvas 232.8/193, ECharts SVG 315.7/197, Plot 445.5/505. ECharts SVG held 50-56 DOM nodes at every rung from 1k to 500k, because a line series is one element.
- (claim) ref=[M-echarts] status=verified class=measurement pub=2026-08 — ECharts 6.1.0 tree-shaken to bar+line+grid+tooltip plus Vue builds to 592,630 B / 206,600 B gzip in one file. renderToSVGString() works on a non-ssr instance in SVG mode, contradicting the handbook; getDataURL({type:'svg'}) silently returns a PNG in canvas mode. The 2019 hidden-container issue does not reproduce against 6.1.0.
- (decision) Verdict: hand-written SVG 93, runner-up Apache ECharts 6.1.0 in SVG mode 84, then Observable Plot 72, uPlot 67, Chart.js 64. The deciding criterion is the printed page (weight 25). Recorded that the same project-decision override applied in R1 and R6 would be defensible here and its shape is ECharts SVG.

Evidenced is only the Bugzilla reporter's own setting plus the printing API's default. Softened in research.md and research-plan.md to a claim that does not depend on the browsers' dialog defaults; the implementation rule is unchanged.
