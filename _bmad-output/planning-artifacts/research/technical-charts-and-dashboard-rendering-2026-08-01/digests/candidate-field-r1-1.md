# Digest — candidate field, licences, vitality — round 1

Researcher: dimension 1. Budget: 14 tool calls, 10 cited sources. Measurement of bundle sizes and
dist-bundle greps was done by the researcher itself, because bundlephobia returned nothing.

## Findings

**The field, as it actually exists on npm today.** A registry search over `keywords:charts` (50 results, retrieved 2026-08-01) surfaces the maintained field and three wildcards not in the brief: **lightweight-charts** (TradingView), **ag-charts-community** (AG Grid), and **apexcharts**, plus `@mui/x-charts`, `visx` and `nivo` [1]. Of the briefed names, only chart.js, echarts, highcharts and @amcharts/amcharts5 rank in that keyword set; uplot, @observablehq/plot, vega-lite, frappe-charts, billboard.js, @unovis/vue, chartist and layerchart do not, which is a discoverability signal rather than a health signal.

**Versions and dates** (npm registry `dist-tags.latest` + `time`, cross-checked against GitHub `releases/latest` where possible): uplot 1.6.32, 2025-03-14 [2][3] · chart.js 4.5.1, 2025-10-13 [2][3] · echarts 6.1.0, 2026-05-19 [2] · @observablehq/plot 0.6.17, 2025-02-14 [2][3] · vega-lite 6.4.3, 2026-04-24 [2] · frappe-charts 1.6.2, 2021-06-16 [2] · billboard.js 4.0.3, 2026-07-06 [2] · @unovis/vue 1.6.7, 2026-06-28 [2] · chartist 1.5.0, 2025-09-30 [2][3] · layerchart 2.0.4, 2026-07-31 [2] · apexcharts 6.6.1, 2026-07-27 [2] · lightweight-charts 5.2.0, 2026-04-24 [2] · ag-charts-community 14.0.2, 2026-07-22 [2] · highcharts 13.0.0, 2026-06-11 [2] · @amcharts/amcharts5 5.20.0, 2026-07-22 [2]. Note a divergence for frappe-charts: GitHub's latest release is v1.6.3 (2022-04-27) but that tag was never published to npm, so the installable artefact is four years older than the repo's own last release and five years old outright [2][3].

**Licences, read from the LICENSE file inside the published package** (fetched via unpkg, not from READMEs) [4]. Permissive and clean: uplot MIT · chart.js MIT (`LICENSE.md`) · echarts Apache-2.0 · @observablehq/plot ISC text (`license`) · frappe-charts MIT · billboard.js MIT (NAVER) · @unovis/ts Apache-2.0 · lightweight-charts Apache-2.0. Not permissive, confirmed rather than assumed: **Highcharts** ships `LICENSE.txt` stating commercial use is governed by the Highsoft Standard License Agreement and non-commercial use by a separate EULA — proprietary, paid, confirmed [4]; the npm `license` field is literally the URL `https://www.highcharts.com/license` [2]. **amCharts 5** ships a "Free amCharts license … provided under linkware license" — free for any project including commercial, but conditioned on displaying an attribution link, i.e. an eligibility/branding-gated free tier, not an OSI licence [4].

**The relicensing event that matters: ApexCharts left MIT inside the 18-month window.** Versions 1.0.1 through 5.0.0 (231 releases) declare `MIT`; 5.2.0–5.3.1 declare `ApexCharts License`; 5.3.2 through the current 6.6.1 (38 releases) declare `SEE LICENSE IN LICENSE` [5]. The switch lands at 5.2.0, published 2025-07-09 — roughly seven minutes after 5.1.0, which reads as a deliberate licence-only cut [5]. The current published LICENSE is a dual-licence model: a free Community License restricted to individuals, non-profits, educators and businesses under **$2 million USD annual revenue**, with commercial terms above that [4]. That is an eligibility-gated free tier and disqualifies ApexCharts from "just add it" status. No other candidate in this set shows a licence-field change in its version history that was checked.

**Bundle size — measured, not looked up.** Bundlephobia's API returned nothing for every package queried (service failure, not a size of zero), so each published dist file was downloaded from unpkg and measured with `gzip -9` [6]. Whole-library UMD/IIFE builds, gzipped: **uplot 22.0 KB** (51.1 KB raw) · **chartist 12.2 KB** (37.8 KB raw) · lightweight-charts 61.6 KB · @observablehq/plot 68.8 KB · **chart.js 70.4 KB** (208.5 KB raw) · vega-lite 79.4 KB · billboard.js 149.4 KB · echarts.simple 168.9 KB · **echarts full 367.9 KB** (1.12 MB raw) · apexcharts 230.3 KB [6]. These are whole-library figures, not tree-shaken; ECharts' own `echarts.simple` build is the vendor-supplied subset and is included to show the achievable floor. The vega-lite figure is the **compiler only** — `vega-lite@6.4.3` declares a peer dependency on `vega ^6`, so the real render-time cost is vega-lite plus the entire Vega runtime, which was not measured [7].

**Vitality over 12 months** (GitHub API, retrieved 2026-08-01) [8]. Genuinely alive: **echarts** (Apache org, 3 releases, 818 issues closed in 12 months, 1571 open, pushed 2026-07-29) · **billboard.js** (NAVER org, 17 releases, pushed 2026-08-01, but only **one npm maintainer** [2]) · **layerchart** (39 releases, pushed 2026-07-31, single maintainer, `techniq`) · **@unovis** (F5 org, 7 releases) · **ag-charts** (16 releases) · **vega-lite** (5 releases). Slowing or stalled: **chart.js** — one release in 12 months and **18 issues closed against 575 open**, which for a 67.6k-star library is a striking throughput collapse [8]. **uPlot** — 10.4k stars, **zero releases in 12 months** (last publish 2025-03-14), last push 2026-04-22, 35 issues closed, 149 open, and one maintainer on npm and GitHub alike [2][8]; low release cadence on a feature-complete library is not the same as abandonment, but the bus factor is one. **Observable Plot** — zero releases in 12 months, last version 2025-02-14, repo still pushed 2026-07-13 [3][8]. **chartist** — one release and **one issue closed** in 12 months, 244 open, one npm maintainer [2][8]. **frappe-charts** — zero releases, **zero issues closed** in 12 months, last push 2025-07-02: dormant [8]. No repository in the set is archived [8].

**Does it fetch anything at runtime?** The published dist bundles were grepped rather than trusting docs [6]. Across uplot, chart.js, echarts (full and simple), @observablehq/plot, chartist, lightweight-charts and vega-lite: **zero** occurrences of `fetch(`, zero dynamic `import(`, zero `new Worker`, zero `wasm`, zero `@font-face`, zero `stylesheet`, zero `XMLHttpRequest` [6]. That is strong evidence that none of them self-loads anything from a bundled IIFE/UMD build. Two exceptions to flag: **billboard.js** contains one `XMLHttpRequest` occurrence and 12 `.css` string hits, and ships a separate `billboard.css` stylesheet its docs require — the XHR reference is unresolved and it could not be determined whether it is reachable code or dead code inside a bundled dependency [6]. **apexcharts** shows 21 `.css` hits and no fetch primitives [6]. ECharts' 24 `.css` hits are consistent with inline style-string parsing, not stylesheet loading, given zero `stylesheet`/`link` matches [6]. Caveat that could not be closed: the UMD/IIFE artefacts were measured; the ESM entry points that Vite would actually consume are different files and were not grepped, and `@unovis/vue`, `layerchart`, `frappe-charts` and `ag-charts-community` were not grepped at all (no single-file bundle at a guessable path, 404) [6].

**In-place mutation of caller-owned arrays: not established.** Searching the issue trackers of Chart.js, ECharts, uPlot, Observable Plot and billboard.js for `Object.freeze` / "frozen" / "read only" returns 12, 6, 2, 1 and 1 hits respectively, and none of them describe a library writing to a caller's data array [9]. The one directly relevant result is Chart.js **#11528, "Charts fail to render when Object prototype is frozen"** (closed) — that is `Object.prototype` being frozen, a different failure mode from a frozen data array, though it does show Chart.js assumes mutability of objects it touches [9]. As a weak structural indicator only, `.sort(` occurs 2× in uplot, 12× in chart.js, 14× in Observable Plot, 19× in billboard.js and 32× in echarts [6] — occurrence counts cannot tell whether any of these sort a caller array or an internal copy, and this is not treated as evidence either way.

## Leads

- **Contradiction — frappe-charts version identity.** GitHub says v1.6.3 (2022-04-27), npm says 1.6.2 (2021-06-16) is `latest` [2][3]. Any writeup quoting "1.6.3" is quoting a tag that was never installable. Treat the npm artefact as the real one.
- **Contradiction — Chart.js "healthy" reputation vs. its own throughput.** 67.6k stars and a 2025-10 release, but 18 issues closed against 575 open in 12 months [8]. Worth checking whether maintenance moved to a v5 branch or whether triage genuinely stalled; the repo's discussions were not opened.
- **billboard.js's XMLHttpRequest occurrence** [6] is the single unresolved disqualifier-shaped finding. Grep the ESM build and locate the call site before trusting or excluding this library; it also requires a separate `billboard.css`.
- **ApexCharts' $2M-revenue gate** [4] should be checked against the actual project's context — and whether the pre-5.2.0 MIT versions remain usable indefinitely (they do, legally, but 5.0.0 is a 2025-07 codebase).
- **layerchart is Svelte-native** (repo `techniq/layerchart`, 39 releases, one maintainer [8]) — no evidence found that it works in Vue 3, and the assumption was not verified either way; likely structurally excluded regardless of its excellent cadence.
- **ECharts' own `echarts.simple` build (168.9 KB gzip)** [6] versus a custom `echarts/core` tree-shaken bar+line build — the latter is the number that would actually decide ECharts, and it needs a real Vite build to measure.
- **uPlot's bus factor of one plus 17 months without a release** [2][8]: check whether `leeoniya` has signalled hand-over or feature-completeness. The 2026-04-22 push against zero releases is the ambiguity to resolve.
- Unexamined wildcards worth a round: `@mui/x-charts` 9.10.1, `visx` 4.0.0, `lightweight-charts` 5.2.0 (Apache-2.0, 61.6 KB gzip, no runtime fetches — but financial-series oriented; does it even do categorical bar charts?).

## Looked for and could not find

- **LICENSE files inside the published packages of vega-lite, chartist, layerchart and ag-charts-community.** Both unpkg filename probes and the jsDelivr file listing returned nothing; only the npm-declared fields are available (BSD-3-Clause; `MIT OR WTFPL`; MIT; MIT) [2], which is the README-adjacent evidence the brief explicitly asked not to settle for. Chartist's `MIT OR WTFPL` dual declaration in particular is unverified against a file.
- **Any size figure from bundlephobia or pkg-size** — the bundlephobia API returned no parseable response for all 14 packages queried. Every size here is the researcher's own measurement of the vendor's dist file [6]; it has not been corroborated by an independent size service.
- **A documented case of any charting library mutating or sorting in place an array handed to it** [9]. Absence of evidence across five issue trackers, not evidence of absence — the searches were title/body keyword searches, and a library could do this silently without anyone filing.
- **Runtime-fetch evidence for @unovis/vue, layerchart, frappe-charts and ag-charts-community** — no single-file bundle at a guessable dist path; not grepped, status unknown [6].
- **Confirmation from npmjs.com package pages** — npmjs.com returns HTTP 403 to this fetcher, so weekly-download figures are absent from this report entirely, and all npm evidence comes from the registry API instead.
- **Any 2025/2026 relicensing, hand-over or dormancy announcement for uPlot, Chart.js, Chartist or Observable Plot** — slowdown was inferred from release and issue metrics only [8]; no statement from any maintainer was found, because there was no budget to read repository discussions.
