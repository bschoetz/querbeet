- (claim) ref=11 status=verified class=compatibility pub=2026-08 — happy-dom's ResizeObserver (packages/happy-dom/src/resize-observer/ResizeObserver.ts, read directly) is a stub: observe()/unobserve()/disconnect() are each '// TODO: Not implemented' and never fire a callback.
- (claim) ref=12 status=verified class=compatibility pub=2026-08 — happy-dom's Element.getBoundingClientRect() (read directly from source) returns 'new DOMRect()' unconditionally, i.e. an all-zero rect; comment reads '// TODO: Not full implementation'. Same failure mode as jsdom.
- (claim) ref=13 status=verified class=compatibility pub=2026-08 — happy-dom's scrollTop/scrollLeft/scrollHeight/scrollWidth (Element.ts, read directly) ARE genuine settable/gettable properties backed by private fields, not hardcoded to zero — a test can set el.scrollTop = N and read it back correctly. This is unlike getBoundingClientRect/ResizeObserver: scrollTop is not computed from real layout, but it is not stubbed either, since nothing in this project's row-window mechanism needs it to reflect actual rendered content height.
- (claim) ref=14 status=verified class=architecture pub=2026-08 — Read directly (project source, not web): ui/RowWindow.vue's untested AD-24 paging branch (v-if="view.pages > 1", the two buttons, disabled states, German labels) depends only on core/view/row-window.js's buildWindow(table, page, scrollTop), which derives .pages from table.rowCount alone (core/view/row-window.js:189-207, pageCount() at :66-69) — it needs no real getBoundingClientRect/ResizeObserver/scrollTop-from-layout at all. A fake props.table with a large rowCount but a sparse/short columns[].cells array reaches the branch, since sliceRows() only reads the small window of indices actually rendered. This is a props-driven Vue reactivity test, not a geometry test — jsdom or happy-dom both suffice for exactly this gap.
