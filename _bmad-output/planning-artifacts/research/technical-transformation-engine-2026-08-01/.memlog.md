- (claim) ref=[D2r2-1] status=verified class=capability pub=2026-08 — RESOLVES the decisive question: Arquero accepts table expressions as STRINGS ('d => op.sqrt(d.value)' or bare 'sqrt(d.value)') and template interpolation; arrow functions take the same path (Arquero toString()s and re-parses them), so a UI-built string is not a degraded mode. escape() additionally allows runtime closures with no source strings. A click-together UI is therefore feasible on Arquero.
- (claim) ref=[D2r2-2] status=verified class=capability pub=2026-08 — Arquero does runtime codegen on every non-escaped expression (src/expression/parse.js ends in compileExpr(generate(node), params)), so a CSP without unsafe-eval breaks all expression use, not just string expressions. escape() is the only codegen-free path but forfeits op aggregates and worker serialization.
- (claim) ref=[D2r2-3] status=verified class=capability pub=2026-08 — CORRECTNESS TRAP: Arquero concat iterates only the FIRST table's columnNames, so columns unique to incoming tables are silently dropped; missing columns fill with undefined (src/util/null.js exports NULL = undefined). Column mapping must precede concat. Directly affects the core union-with-mapping use case.
- (claim) ref=[D2r2-4] status=verified class=capability pub=2026-08 — Arquero hashJoin emits the full cartesian product on duplicate keys (standard SQL semantics); API docs never warn about row-count blow-up. String expressions and escape() have NO test coverage in test/verbs/filter-test.js or test/expression/parse-test.js: documented but untested.
