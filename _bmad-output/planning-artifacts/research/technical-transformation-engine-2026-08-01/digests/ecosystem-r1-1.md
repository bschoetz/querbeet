## Leads

- Read AlaSQL issues #2464, #2479, #2480, #609 — #2481's author flags them as a related cluster of aggregate/NULL/date correctness reports; that cluster would show whether the 2026 correctness reports are one reporter or many.
- Determine what the Nov 2025–Jan 2026 AlaSQL burst actually was. Commits show a `Copilot` author alongside `mathiasrw` and a closed PR "[WIP] Fix incorrect results in SQL query execution" (#2405, opened and closed within a day). If long-open correctness bugs were closed by AI-generated patches, ask what test evidence accompanied them before treating those closures as fixes.
- Ask Arquero directly: open or find an issue about release plans. 14 months of silence with an active maintainer elsewhere is ambiguous between "finished" and "dropped"; a maintainer statement would settle it.
- Pin down DuckDB-WASM's stable-vs-dev release policy — the npm `latest` tag being a `-dev` build is a real operational question for a tool that must be pinned for years. Check the repo's release docs or a maintainer statement from `carlopi`.
- Verify AlaSQL's and DuckDB-WASM's LICENSE file bodies directly (this run relied on SPDX detection for those two).
- Empirical differential test: run the exact merge/join/group-by shapes on AlaSQL vs DuckDB-WASM vs Arquero over the same fixture. Given AlaSQL's documented join limitations, a 30-line harness would produce decisive first-party evidence that no amount of issue-tracker reading can.
