## Leads

1. **DuckDB-WASM's stable-release gap is the single biggest open question.** npm `latest` = `1.33.1-dev57.0`; last non-prerelease on npm = 1.32.0 (2025-12-16); last GitHub release tag = v1.33.0 (2025-12-16). Someone must determine whether the project considers the dev channel the supported one, and whether the open regressions (#2219 module instantiation, #2192 OPFS durability) affect the mvp/eh bundles or only coi/OPFS paths. Chase: duckdb-wasm README/docs and the release-process discussion.
2. **Single-HTML-file feasibility is unresolved for every WASM candidate.** DuckDB-WASM, sql.js and Perspective all ship `.wasm` + Worker files as separate artifacts. Whether base64-inlining a `.wasm` into one HTML file is practical at these sizes — and whether each library supports instantiating from an inlined buffer without a same-origin worker URL — is the decisive engineering question and was not answered this run.
3. **Contradiction to resolve: sql.js license.** npm reports MIT; GitHub's detector reports NOASSERTION. Read the repo LICENSE file directly.
4. **Arquero dormancy — intent unknown.** 14 months of no commits with a small, un-triaged issue queue. Is this "finished" or "orphaned"? A maintainer statement (Jeff Heer / UW IDL, or the Mosaic project's positioning) would settle it. Consequence differs sharply: a stable, feature-complete BSD library is usable; an orphaned one is not.
5. **Arquero CSP issue #361 (open since 2025-10) suggests runtime codegen.** If the target tool must run under strict CSP, this is a possible hard gate on Arquero that was not confirmed this run.
6. **Unexamined actives worth one look each:** `@electric-sql/pglite` 0.5.4 (2026-07-02, WASM Postgres) and `@wrenai/wren-core-wasm` 0.4.1 (2026-05-15, DataFusion-in-browser). Both are shipping in 2026 and neither would appear on a 2024 shortlist.
7. **Perspective's fit is unclear.** It is the second-most-active candidate and permissively licensed, but packaged as a viewer web component. Whether its engine (`@perspective-dev/client`) is usable headlessly as a pipeline transform layer needs checking.
8. **AlaSQL's 460 open issues vs. steady releases.** Correctness under joins/aggregations at 100k rows is the thing to verify — a SQL engine that releases often but carries a large backlog is a correctness risk, not just a support risk.
