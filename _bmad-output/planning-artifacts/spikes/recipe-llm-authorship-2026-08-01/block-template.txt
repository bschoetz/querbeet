## 4. Das Rezept-Format: querbeet/recipe@1

### Der Rahmen

Ein Rezept ist genau ein JSON-Objekt:

    {
      "format": "querbeet/recipe@1",
      "name":   "Kurzer Name des Rezepts",
      "sources": [ ... ],
      "steps":   [ ... ],
      "result":  "kennung-eines-steps"
    }

Diese fünf Felder sind Pflicht. Zusätzliche Felder werden ignoriert.

Ein Rezept enthält niemals Daten: keine Zeilen, keine Zellwerte. Nur Struktur.

### Kennungen

Jede Quelle und jeder Step hat eine `id` — ein kurzes Kürzel aus Buchstaben,
Ziffern und Bindestrichen: `q1`, `umsatz`, `f-region`. Kennungen sind über
`sources` und `steps` hinweg eindeutig; keine darf zweimal vorkommen. Verwiesen
wird immer über die `id`, nie über den Namen.

Die Reihenfolge der Einträge ist egal. Ein Step darf einen Step nennen, der
weiter unten steht.

### Quellen

Eine Quelle ist eine Datei, die ich lade. Du erfindest keine Quellen — es gibt
genau die, die unter „Meine Quellen“ stehen, mit genau diesen Kennungen und
Spaltennamen.

    {
      "id": "umsatz",
      "name": "Umsätze 2026",
      "file": "umsatz-2026.csv",
      "columns": ["Datum", "Kunde", "Betrag"],
      "ui": { "x": 0, "y": 0 }
    }

Quellen stehen ausschließlich in `sources`, nie in `steps`. Sie haben keine
Eingänge.

### Steps

    {
      "id": "f1",
      "name": "Nur Region Süd",
      "kind": "filter",
      "inputs": "umsatz",
      "config": { "conditions": [ { "column": "Region", "op": "equals", "value": "Süd" } ],
                  "combine": "and" },
      "ui": { "x": 260, "y": 0 }
    }

`kind` ist genau eine dieser drei Arten:

    kind     Eingänge       wofür
    union    2 oder mehr    gleichartige Tabellen untereinander hängen
    join     genau 2        zwei Tabellen über Schlüsselspalten verbinden
    filter   genau 1        Zeilen behalten, die Bedingungen erfüllen

Andere Arten gibt es nicht. Wenn meine Frage etwas verlangt, das keine dieser
drei kann — gruppieren, summieren, rechnen, sortieren, Spalten umbenennen oder
löschen —, dann schreib mir das hin, statt eine Art zu erfinden. Ein Rezept mit
einer erfundenen Art wird abgelehnt und hilft mir nicht.

### inputs

`inputs` nennt die Kennungen der Vorgänger in fester Reihenfolge:

    ein Eingang:   "inputs": "umsatz"
    mehrere:       "inputs": ["umsatz", "kunden"]

Beim Join ist die Reihenfolge bedeutungstragend: der erste Eintrag ist die
linke, der zweite die rechte Tabelle.

### config je Art

union — Tabellen untereinander hängen:

    { "mappings":  [ { "target": "Zielspalte", "from": "Quellspalte" } ],
      "unmatched": "keep" }

`mappings` benennt Spalten um, die in den Eingängen unterschiedlich heißen.
Heißen sie überall gleich, ist `"mappings": []` richtig. `unmatched` ist `keep`
(Spalte, die ein Eingang nicht hat, bleibt leer) oder `drop` (solche Spalten
verwerfen).

join — zwei Tabellen über Schlüsselspalten verbinden:

    { "keys": [ { "left": "Kundennr", "right": "Nr" } ],
      "type": "left",
      "nullsMatch": false,
      "duplicateAudit": false }

`left` ist eine Spalte des ersten Eingangs, `right` eine des zweiten. `type` ist
`left` (alle Zeilen links behalten) oder `inner` (nur Treffer). `nullsMatch`
entscheidet, ob leer auf leer passt — normalerweise `false`. `duplicateAudit`
meldet, wenn ein Schlüssel rechts mehrfach vorkommt und Zeilen dadurch
vervielfacht werden.

filter — Zeilen behalten:

    { "conditions": [ { "column": "Region", "op": "equals", "value": "Süd" } ],
      "combine": "and" }

`op` ist `equals`, `contains` oder `gt`. `combine` ist `and` oder `or`.

Spaltennamen schreibst du wörtlich so, wie sie unter „Meine Quellen“ stehen —
mit Groß- und Kleinschreibung, Umlauten und Leerzeichen. querbeet prüft jeden
Spaltennamen gegen die Spalten, die an diesem Step tatsächlich anliegen, und
lehnt das Rezept sonst ab. Denk dabei den Weg mit: nach einer Union mit
`"unmatched": "drop"` gibt es nur noch die Spalten, die alle Eingänge haben,
und nach einer Zuordnung heißt die Spalte so, wie `target` sagt.

Fehlt `config`, setzt querbeet die Voreinstellung der Art ein.

### result

`result` nennt die Kennung des einen Steps, dessen Tabelle das Ergebnis ist.
Genau einer. Er muss in `steps` stehen — eine Quelle kann nie das Ergebnis sein.

### ui

`ui` ist die Position im Editor. Setz die Quellen links untereinander (x = 0,
y in Schritten von 140) und staffle die Steps in Flussrichtung nach rechts
(x in Schritten von 260). Lässt du `ui` ganz weg, ordnet querbeet die Steps
selbst von links nach rechts an — gib es trotzdem an, du weißt besser als das
Werkzeug, was nebeneinander gehört.

### Was querbeet ablehnt

Ein Rezept wird ganz angenommen oder ganz abgelehnt. Nichts wird halb geladen.
Abgelehnt wird:

    ungültiges JSON            Das ist kein gültiges JSON: ...
    doppelte Kennung           Die Kennung „q1“ kommt mehrfach vor.
    Verweis ins Leere          „F“ verweist an Eingang 1 auf „gibtsnicht“, das es nicht gibt.
    falsche Anzahl Eingänge    „J“ ist ein Join und nimmt genau 2 Eingänge, das Rezept nennt 1.
    unbekannte Art             „P“ hat die unbekannte Step-Art „pivot“.
    fehlendes Ergebnis         Das Rezept weist keinen Ergebnis-Step aus.
    Ergebnis ist eine Quelle   Der ausgewiesene Ergebnis-Step „q1“ ist eine Quelle.
    Kreis im Graphen           Der Graph enthält einen Kreis: Filter → Filter 2 → Filter.
    Quelle unter steps         „B“ ist eine Quelle und gehört unter „sources“, nicht unter „steps“.
    Spalte gibt es nicht       „F“ filtert auf die Spalte „Abteilung“ (Bedingung 1), aber sein
                               Eingang hat sie nicht. Verfügbar: Bestellnr, Datum, Betrag.

Geh dein Rezept gegen diese Liste durch, bevor du antwortest. Schicke ich dir
eine dieser Meldungen zurück, korrigier genau das und gib mir das ganze Rezept
neu — nicht nur den geänderten Teil.

### Wenn du erst Werte sehen musst

Du bekommst keine Daten. Musst du vorher etwas wissen — welche Regionen
vorkommen, ob eine Spalte eindeutig ist, wie ein Datum geschrieben ist —, dann
antworte statt eines Rezepts mit einer Probe-Abfrage: dasselbe Format, aber
zusätzlich `"purpose": "probe"`, und der Ergebnis-Step zeigt genau das, was du
wissen willst. Ich lasse sie lokal laufen, sehe das Ergebnis selbst und schicke
dir nur dieses Ergebnis zurück.
