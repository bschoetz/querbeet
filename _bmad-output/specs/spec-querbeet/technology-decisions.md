# Technology Decisions — querbeet

Companion to `SPEC.md`. What was picked, why, and which picks **overrode the research verdict**. This last part is why the file exists: a reader who finds only the pick would assume the research chose it, and would then be free to "correct" four of these back to a verdict the project deliberately declined.

**Authority on version pins is the spine's Stack table** (`ARCHITECTURE-SPINE.md`), which was re-verified against the live registries on 2026-08-02. The versions below are the ones each decision was taken against; where the two differ, the spine is right and this file is history.

Research runs live at `_bmad-output/planning-artifacts/research/` and spikes at `_bmad-output/planning-artifacts/spikes/`. They are apparatus, not contract — cited here so the reasoning is recoverable, not adopted as companions.

## The decisions

| Concern | Decision | Why |
| --- | --- | --- |
| Transformation engine | **Arquero 8.0.3**, pinned, vendored | R1. **Overrides the research verdict**, which recommended hand-written functions (94 vs 68 on the matrix). The project owner chose a complete, widely used library over freshly written bespoke code; the research's own C5 criterion and its stated case-against support that reading, and the deepening revised Arquero's ecosystem score upward on measured fork cost and tenfold adoption growth. |
| UI framework | **Vue 3.5.40** | R2. 88/100; runner-up Preact + htm at 80, Alpine at 76. Re-examined in R6 against the graph-editor criterion rather than the list of heterogeneous steps it was originally scored against, and it survived. |
| Delivery | **Vite 8 + `vite-plugin-singlefile`** emitting one HTML file | R2 deepening. **Overrides the report's no-build recommendation**, trading toolchain risk for real Single-File Components. Measured: one 280,519-byte file working from `file://` in Chromium 150 and Firefox 153, about 121 KB *smaller* than the no-build path. The Vite major was left open by research and **settled by building on 2026-08-02** — Vite 8.2.0 with the plugin at 2.3.3 emits one file and the assertion passes. One build-config consequence travels with it and lives in spine AD-17. |
| CSV | **PapaParse 5.5.4**, `dynamicTyping` permanently off | R3. Automatic type coercion in the parser is off forever; typing is Step zero and nowhere else. |
| Encoding | **No library.** BOM sniff → strict UTF-8 probe → Windows-1252 fallback → user override | R3. |
| XLSX | **`write-excel-file` 4.1.1 + `read-excel-file` 9.3.5** behind a thin adapter | R3. 88 vs 61 against SheetJS CE, which is 334 KB gzipped, paywalls cell styling, and has shipped no release in two years. SheetJS remains the drop-in fallback: the chosen pair is a single-author project, and the adapter is roughly fifty lines. |
| JSON repair | **`jsonrepair` 3.15.0**, only after `JSON.parse` fails | R3. |
| JSON preview | **`json-formatter-js` 2.5.23** | R3. |
| JSON flattening | **Own code** | R3 — three maintained libraries chose three different array semantics, which is evidence there is no safe default. Hence CAP-7's explicit user choice. |
| Parquet write | **`hyparquet-writer` 0.16.3**, Snappy default | R3. Round-trip verified against pyarrow 25, DuckDB 1.5.5 and Polars 1.43.2. Its `GZIP` codec silently writes an unreadable file — do not reach for it. |
| Parquet read | **`hyparquet` 1.27.1** — the writer's own dependency | R3 measured the pair at 33,439 bytes gzipped together against 17,239 for the writer alone, so reading costs about 16 KB on top. Same authors, zero dependencies, MIT, and the better-established of the two. |
| Table rendering | **Hand-rolled fixed-height row windowing**, ~50-row window; no column virtualization | R4. 94 vs 92 for TanStack Virtual — close enough that adopting the library instead is a reasonable deliberate trade, which is why the windowing sits behind a component whose props are `(rows, rowHeight, windowSize)`. |
| Graph Editor | **Vue Flow 1.48.2** | R6. **Overrides the research verdict**, which scored a hand-built SVG canvas at 85 against Vue Flow's 75, on the same reasoning that decided the engine. MIT with no paid tier and no runtime key, verified in the shipped LICENSE. Two findings became mandatory work rather than observations — see `measured-constraints.md`. |
| Charts | **Apache ECharts 6.1.0, SVG renderer only** | R7. **Overrides the research verdict**, which scored hand-written SVG at 93 against ECharts' 84 — a margin carried entirely by footprint, the one criterion the framework and editor decisions had each already ruled out; without it the two tie at 92 to 91. Apache-2.0. Decided on battle-testedness, and the edge-case tripwire confirmed it: eight cases, both engines, no throw and zero `NaN` in any serialized SVG. |
| Number parsing | **No library.** Separators read from `Intl.NumberFormat.formatToParts`, parsing in own code | R5. Runner-up `@internationalized/number` 3.6.7, which passed the single-file gate but has neither its size nor its throughput measured. The platform already knows a locale's decimal and grouping characters; what it does not do is decide between two readings, which is querbeet's own logic either way. |
| Date parsing | **`date-fns` 4.4.0**, `parse` with an explicit pattern | R5. Runner-up `d3-time-format` — stricter and about 500 B per locale object, at the price of maintaining the locale table yourself. **Temporal is not an option:** `PlainDate.from()` accepts only RFC 9557 strings, so `"31.12.2025"` throws, and Safari does not ship it. |
| Type record | Per column `{type, decimalChar, groupChar, dateFormat, missingValues, keepOriginal}`, stored in the Recipe | R5. **This is what CAP-9's confirmation actually persists.** Runner-up was CSVW's `format` object — the same content inside a much heavier document model. The shape is deliberately close to Power Query's `Table.TransformColumnTypes(…, culture)`, the best override prior art found: it asks for a type and a locale in one action and serialises the culture into the saved script. |
| CSS | **Tailwind v4.3.3**, with `preflight.css` omitted from the three-line split import | R5. The freshness rule decided it — Pico 2.1.1 is 16 months old, Bulma 15, Simple.css 14, Water.css 59; only Tailwind, UnoCSS and Open Props are current. The single-file gate separated nothing: zero `@font-face` rules in any candidate and every `url()` already a `data:` URI, the editor library's two stylesheets included. Cost scales with querbeet rather than with the package — `tailwindcss/utilities.css` as published is **21 bytes**, every utility generated from the app's own markup, against a classless framework shipping its whole sheet regardless (Pico 83 KB raw, Bulma 678 KB). |
| Session persistence | **IndexedDB**, no library | R9. Works from `file://` in both engines and survives a browser restart, so CAP-25 is buildable as written. Storage costs about a tenth of the heap: 100k × 20 rows occupy 8.9 MB stored against ~94 MB live. One consequence reaches C-8 — see `measured-constraints.md`. |

## Standing facts about these picks

- **Arquero has had no upstream commit in fourteen months.** A fork plan is kept on file rather than a fork: 10,764 lines, 392 passing tests, two dependencies, BSD-3-Clause. Realistic to adopt if a blocking bug surfaces; recorded so the option is remembered rather than rediscovered under pressure.
- **The build step is mandatory, not optional.** `hyparquet-writer` is ESM-only with no published UMD bundle, so keeping Parquet in scope (CAP-36) converts the Vite build from permitted to required. Everything else in the stack ships a ready-made UMD artifact.
- **`hyparquet-writer` 0.16.4 shipped 2026-08-01**, one patch ahead of the pin.
- **`read-excel-file` 9.3.5 hardcodes `CAN_USE_WORKER = false`**, so it never constructs the worker an earlier open question worried about, and its dedicated worker export should not be reached for. It does spawn its own fflate blob-URL workers on the import path, which is why `new Worker` is not a usable gate signal on the built artifact.
- **Arquero requires `unsafe-eval`** for dynamic function compilation per its open issue #361. Using `escape()` throughout may avoid it; untested. Only matters if the page ever imposes a policy on itself.
- **What is not yet decided:** the Package container format and the view-document mechanism. Both are open questions in `SPEC.md`. The Vite major was the third of these and is closed.
